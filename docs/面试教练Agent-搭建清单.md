# 面试教练 Agent 搭建清单（Java 后端 + 前端 + Agent + RAG）

> 目标：在通用 Agent 平台（Qoder 自定义 Subagent / Claude Code / 任何支持 SKILL.md 或系统提示词的工具）上，搭一个**只为你一个人服务的面试教练**。
> 用法：从上往下逐条做，每条都有「验收标准」，打勾了才进下一步。
> 原则：你负责搭，Agent 负责陪练；**Agent 不允许编造你的项目事实**（这是红线，写进它的设定）。

---

## 0. 先想清楚三件事（动工前 10 分钟）

| # | 想清楚什么 | 参考结论 |
| --- | --- | --- |
| 1 | 它不是"知识搜索器"，是**教练** | 教练的动作是：出题 → 逼你答 → 追问 → 点评 → 留作业。只答不问的是百科 |
| 2 | 目标场景只有两个 | ① 每天 20~30 分钟模拟面试；② 汇报/真面前突击核对"项目怎么讲" |
| 3 | 红线三条 | 不编造你的经历；不替你编简历；不确定时反问你而不是硬编 |

## 1. 能力范围：四域矩阵（先定边界，避免做成四不像）

| 域 | 必须覆盖的高频考点 | 你项目里的证据（它被问到时能引用的真实素材） |
| --- | --- | --- |
| Java 后端 | 线程池、ThreadLocal、Spring 注解与依赖注入、拦截器、JDBC 与事务、HTTP 状态码语义 | `WorkflowService`（异步+权限）、`UserContext`、`AuthInterceptor`、`WorkflowTaskRepository`、409 的处理 |
| 前端 | Vue3 组合式 API 与响应式、路由、fetch/轮询/SSE、前后端分工 | `WorkflowView.vue`（轮询/流程条/导出）、`api.js`、`RagView`（SSE 流式） |
| Agent 开发 | 工具调用、意图识别、条件分支、状态机、人工确认、异常兜底、Skill/工具的区别 | `DocWorkflow`（六节点图）、`WorkflowService`（状态机）、`KbStatsTool`/`HttpTimeTool`、`OfficialDocFormatSkill` |
| RAG | 切块与入库、embedding、向量检索 vs 关键词、RRF、rerank 降级、引用标注、拒答策略、评测方法 | `HybridRetrievalService`、`RagWorkflow`（重试环+确定性拒答）、`eval_rag.py`、`logs/eval_report.md` |

**验收**：四域每域能用一句话说出"我项目里哪个文件能证明我会这个"。说不出的，先去补那个文件的理解。

## 2. 目录结构：两个方案选一个

### 方案 A：Skill 文件夹（推荐，Qoder / Claude Skills 通用）

```
interview-coach/
├── SKILL.md                 # 角色 + 工作流程 + 红线（建议 ≤200 行）
├── references/
│   ├── 项目事实卡.md         # ★ 最重要：你的项目真实数据，防编造
│   ├── 题库-java.md
│   ├── 题库-前端.md
│   ├── 题库-agent.md
│   ├── 题库-rag.md
│   ├── 评分标准.md           # 四档 rubric
│   └── 回答模板-STAR.md
├── scripts/
│   ├── draw_question.py     # 从题库随机抽一题
│   └── record_mistake.py    # 把错题追加到错题本
└── 错题本.md                 # 运行时产物，脚本追加
```

### 方案 B：自定义 Subagent（本 IDE 左侧技能列表里有 `create-subagent` / `create-skill`，可直接调用）

- 把 `SKILL.md` 的内容粘进 Subagent 的系统提示词；
- `references/` 里的文件路径写进提示词，让它**按需读取**而不是全部塞进去（省上下文）。

**两方案的区别**：A 是"随取随用的技能包"，B 是"常驻的专家角色"。想每天喊一句"练 30 分钟"就用 B；想在不同工具里复用就用 A。

**验收**：能画出目录树，说清每个文件干什么。

## 3. 分步搭建（每步带验收）

### Step 1：建目录 + SKILL.md 骨架（30 分钟）

SKILL.md 只写四块，别贪多：

```markdown
# 面试教练（四域版）

## 身份
你是我的 Java 后端 + 前端 + Agent + RAG 面试教练。
你的素材只来自两个地方：references/ 里的文件，和我的现场回答。
你不了解我简历以外的任何经历，**禁止编造我的项目细节**；不确定时直接问我。

## 工作流程（模拟面试协议）
1. 每次开始先问我：今天练哪个域？练几题？（默认 3 题）
2. 一次只问 1 道题，等我答完再说话。
3. 我答完后：先肯定一个亮点 → 再指出一个漏洞 → 追问 2 个（1 个"为什么"，1 个"如果……怎么办"）
4. 每道题结束用四档评分（见 references/评分标准.md），并给一句"更标准的答法"
5. 我连续两次答不上 → 停止追问，讲解并记入错题本
6. 结束输出本次报告：得分、两个薄弱点、三个下次复习任务

## 素材使用规则
- 出题优先从 references/题库-<域>.md 抽；题库没有的考点可以现场出，但要标注"题库外"
- 点评涉及项目事实时，必须和 references/项目事实卡.md 一致；对不上就不引用
- 我答错且事实卡没有依据时，说"这个我不确定，需要你核对代码"，不许猜

## 语气
直接、不说客套话；我摆烂时提醒我回到节奏。
```

**验收**：把这段发给 Agent，它能复述"一次只问一题"和"禁止编造"两条规则。

### Step 2：写项目事实卡（1 小时，最重要的一步）

这张卡是**防幻觉的锚**：Agent 点评你的答案时只能引用卡里的事实。格式统一：

```markdown
## 事实卡（每条必须有来源文件）

| # | 事实 | 来源 |
| --- | --- | --- |
| 1 | 工作流是异步任务+轮询：接口立刻返回 RUNNING，图在 workflowExecutor 里跑，前端每 2 秒轮询 | WorkflowService.create / WorkflowView.schedulePolling |
| 2 | 任务状态机 6 个状态：RUNNING→PENDING_CONFIRM→CONFIRMED/REJECTED→EXPORTED，异常→FAILED | WorkflowTask |
| 3 | 未确认导出返回 409，靠带前置状态的条件 UPDATE（WHERE id=? AND status=?） | WorkflowTaskRepository.transition |
| 4 | 图有 6 个节点：classify/retrieve/generate/formatCheck/stats/chat，2 个工具分支 | DocWorkflow |
| 5 | 意图分类用 JSON 模型输出 {intent, keywords}，失败兜底 QA 并记 fallback | DocWorkflow.classify |
| 6 | 空上下文确定性拒答：不调模型，直接返回资料不足 | RagWorkflow.generate / DocWorkflow.generate |
| 7 | 混合检索=向量 + 关键词 ILIKE，RRF(1/(60+rank)) 融合后 rerank，rerank 挂了降级回 RRF | HybridRetrievalService |
| 8 | Skill 是纯规则引擎 8 条（R1~R8），ERROR 扣 20、WARN 扣 8，passed 只看 ERROR | OfficialDocFormatSkill |
| 9 | 权限校验放在请求线程做（ThreadLocal 不跨线程），异步只传已校验的 kbIds | WorkflowService.create |
| 10 | PG 拿主键必须 prepareStatement(sql, new String[]{"id"})，否则 getKey() 抛异常 | WorkflowTaskRepository.insert |
| 11 | 评测 15 题（10 有答案+5 无答案），实测 100% 命中 / 100% 拒答 / 100% 引用标注 | logs/eval_report.md |
| 12 | 无答案题平均 9.7s（2 次重试），有答案题 4.1s（0 次） | logs/eval_report.md |
| 13 | 全链路验证脚本 32 项断言全部 PASS | scripts/verify_workflow.py |
| 14 | Skill 曾误报：全角空格 U+3000 导致 R5 找不到行首"一、"，修复后 72→100 分 | OfficialDocFormatSkill 注释 |
| ... | （按需补到 20~30 条；每条都必须是代码或报告里查得到的） | |
```

**验收**：随机抽第 7、9、13 条，你都能在 30 秒内找到来源文件对应位置。

### Step 3：建题库（先每域 15 题，别贪多）

统一格式（一条题目就是一个块）：

```markdown
### J01 线程池/异步
- 问题：为什么工作流接口要异步？同步会怎样？
- 考点：长任务与 HTTP 超时、线程池
- 追问：ThreadLocal 在异步线程为什么丢？你项目怎么解决的？
- 参考要点：图执行 20~90s → 网关 30s 超时；丢进 workflowExecutor 立刻返回；权限检查留在请求线程
- 项目锚点：WorkflowService.create / WorkflowService.execute
```

初始素材来源（都是现成的）：

| 来源 | 怎么用 |
| --- | --- |
| `docs/W4学习文档-公文工作流与RAG评测.md` 第 8.2 节 12 道自检题 | 直接转成 12 条题目 |
| `docs/项目学习导读.md` 的"10 个问题点" | 转成项目深挖题 |
| `logs/eval_report.md` | 转成 RAG 评测方法论题（命中率怎么算/为什么关键词组制） |
| 面经（牛客/BOSS/同学反馈） | 每看到一题，按下面"转化三问"处理后再入库 |

**转化三问**（面经变题库的标准动作）：
1. 这题考什么知识点？
2. 我项目里哪段代码能当证据？
3. 面试官追问会往哪深挖一层？

**验收**：四域各 15 条，每条都有"追问 + 项目锚点"两个字段（缺这两个的题目不合格，会在实战中被追死）。

### Step 4：写评分标准（20 分钟）

四档 rubric，逼 Agent 宁可低一档：

| 档位 | 表现 | 典型话术 |
| --- | --- | --- |
| A 能权衡 | 说出方案 + 备选 + 为什么选它 + 代价 | "轮询简单但用户多了要换 SSE，我们量级小选了轮询" |
| B 理解 | 说出方案 + 原因，说不出代价/备选 | "因为超时所以异步" |
| C 背过 | 能复述名词，追问就断 | "用了 RRF，就是……排名融合吧" |
| D 不会 | 答不出或答错 | — |

规则：**"宁可低一档"**——B 档答案里如果出现"应该/大概/好像"这类词，降级为 C。

**验收**：拿你自己对"RRF 为什么不用分数加权"的真实回答，让 Agent 打分，档位和你自评差不超过一档。

### Step 5：写模拟面试协议（已经包含在 Step 1 的骨架里）

如果你想要更细，把协议写成状态机（Agent 照做）：

```
开始 → 选域/题数 → 抽题 → 我答 → 亮点 → 漏洞 → 追问1(为什么) → 追问2(如果…怎么办)
                                                        ├→ 连续2次答不上 → 讲解 + 记错题 → 下一题
                                                        └→ 通过 → 下一题
全部答完 → 输出报告（得分/薄弱点×2/复习任务×3）→ 结束
```

**验收**：跑一轮 3 题，全程它没有一次"一口气问两道题"。

### Step 6：脚本（可选，但强烈建议做"记错题"）

最小可用版本就够了：

```python
# scripts/record_mistake.py  用法: python record_mistake.py "J01 线程池异步" "说不出 ThreadLocal 为何丢"
import sys, pathlib, datetime
root = pathlib.Path(__file__).resolve().parent.parent
line = f"- [{datetime.date.today()}] {sys.argv[1]}：{sys.argv[2]}\n"
with open(root / "错题本.md", "a", encoding="utf-8") as f:
    f.write(line)
print("已记录:", line.strip())
```

抽题脚本同理：读 `题库-<域>.md`，按 `### ` 分块随机取一块打印。

**验收**：执行一次，错题本多了一行；Agent 在会话结束时能提示你"运行 record_mistake.py 记录本条"。

### Step 7：验收测试（5 个场景，全过才算搭完）

| # | 场景 | 通过标准 |
| --- | --- | --- |
| 1 | 说"练 RAG，3 题" | 只问 1 题；题目来自题库-rag.md |
| 2 | 故意答一个错误事实（"我项目用的是 MySQL 主键自增"） | 它依据事实卡纠正你（PostgreSQL） |
| 3 | 问它事实卡之外的事（"我项目日活多少"） | 它说不知道/反问你，不编 |
| 4 | 同一题连续两次答不上 | 停止追问并讲解，提示记错题 |
| 5 | 跑完 3 题 | 输出报告：得分 + 2 个薄弱点 + 3 条复习任务 |

**验收**：5 条全过 → 你的 Agent 出师。有一条不过 → 回对应 Step 改提示词。

## 4. 坑位清单（都是会真实遇到的）

1. **题库别全塞进 SKILL.md**：150 道题全塞进去，其他上下文就没地方了。原则：SKILL.md 只放"怎么做事"，题库放 references 按需读。
2. **事实卡必须可查证**：写"记得好像是 100%"就废了。每条都要能指到代码/报告里的位置。
3. **一次只问一题**：写进协议。新手教练 Agent 最常见的毛病是一口气甩 5 个问题，你答不完也评不了。
4. **评分要防虚高**：加"宁可低一档"和"出现大概/应该就降档"两条，否则它天天给你 A。
5. **追问必须分两类**：1 个"为什么这么设计"，1 个"如果换个条件怎么办"。只问 why 的追问练不出应变。
6. **别让它替你想简历**：红线写死——只练你真实做过的事，没做过的直接说"没做过"。
7. **每周回填新题**：真实面试被问倒的题，当晚按"转化三问"入库，否则题库永远停在初始状态。
8. **双 Agent 防放水（进阶）**：出题官和评分官拆成两个 Subagent，互相不给面子，评分可信度更高。

## 5. 上线之后怎么用（节奏建议）

| 时机 | 动作 | 时长 |
| --- | --- | --- |
| 每天固定时间 | 练一个域，2~3 题，结束看报告 | 20~30 分钟 |
| 汇报/真面前 1 天 | 让它用"项目事实卡"抽查你讲项目（问 5 个深挖题） | 30 分钟 |
| 每周日 | 打开错题本，重练本周错的题 | 20 分钟 |
| 每次真实面试后 | 被问倒的题按"转化三问"入库 + 记错题 | 10 分钟 |
