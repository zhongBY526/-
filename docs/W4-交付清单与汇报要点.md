## 三、失败案例归因（3 条评测/边界 badcase）与优化措施（1 条）

> 2026-11-26 16:13 复跑 15 题：命中率 100%、拒答率 100%、引用标注率 100%。以下 3 条是复跑之外主动探测出的真实 badcase，均可现场复现，证据在 `logs/badcase_probe.json` / `logs/badcase_probe2.json`。

1. **【召回】无答案题仍展示无关引用**
   - 现象：Q11~Q15 都正确拒答，但每道题仍附带 3 条与问题无关的引用（如年假题命中《优化营商环境条例》）。
   - 根因：`HybridRetrievalService` 的 `min-score=0.3` 只作用于向量通道初筛，rerank 后仍按 `final-top-k=5` 返回并展示，低分引用没有在展示层过滤。
   - 改进：首轮 rerank top1 低于阈值时直接确定性拒答、跳过改写重试，并隐藏低分引用；列入 W5 优化。

2. **【精排】引用精度不足**
   - 现象：Q09「药品经营和使用质量监管职权」混入 `21_医疗器械经营监督管理办法`；Q01 引用 `04_医疗器械监督管理条例` 段落 26/38，rerank 分数仅 0.185/0.058。
   - 根因：混合检索关键词/向量召回噪声，rerank 后未按分数截断，top5 内低分文档仍进入生成与引用。
   - 改进：增加 rerank 分数阈值 + 引用去重；现场抽 2 题人工核对答案原文。

3. **【生成】条款类问题误拒答**
   - 现象：问「医疗器械经营企业应建立哪些质量管理记录、保存期限多久」，《医疗器械经营监督管理办法》第三十二/三十八条已有明确答案（有效期后 2 年 / 无有效期不少于 5 年 / 植入类永久），系统 2 次重试后仍拒答，耗时 29.5s。
   - 根因：拒答 prompt 对「资料不足」判定过严，把「问题问法泛化」误判为资料缺失；2 次改写重试进一步放大延迟。
   - 改进：先判断检索片段是否含答案要素，再决定是否改写；条款类问题直接生成，不触发重试。

**优化措施（有数据支撑）**：无答案题平均耗时 10.8s（均触发 2 次检索重试）vs 有答案题 5.3s（0 重试），且拒答时仍附带 3 条不相关引用。
措施：首轮 rerank top1 分数低于阈值时直接确定性拒答、跳过改写重试，并不再展示不相关引用——预期无答案题延迟从 ~10.8s 降到 ~4s，拒答更干净。

### 附：开发期修复的 3 个工程缺陷（可作为设计讲解素材）

1. **Skill R5 层次序数误报**（已修复）
   - 现象：DRAFT 草稿明明有"一、自查对象和范围"，R5 仍报"缺少上级一、级"，score 被误扣到 72。
   - 根因：正则 `(?m)^一、` 在原始文本上匹配，而公文正文行首是全角空格 U+3000 缩进，"一、"不在行首。
   - 修复：正则改为 `^[\s\u3000]*一、`，行解析先把全角空格归一化；重跑后 score=100。
   - 教训：中文公文场景必须考虑全角空白；规则引擎要用真实生成样本回归。

2. **JSON 模型无法生成公文正文**（已修复）
   - 现象：复用 `openAiJsonChatModel` 生成草稿，输出被强制成 JSON 而非公文文本。
   - 根因：该模型配置了 `response_format=json_object`，适合结构化抽取/分类，不适合自由文本。
   - 修复：新增 `WorkflowModelConfig.workflowChatModel`（普通文本，temperature 0.3）；JSON 模型只用于意图分类。

3. **异步线程丢失登录上下文**（已规避）
   - 现象：工作流丢进线程池后调用 `requireAccess` 抛未授权。
   - 根因：`UserContext` 基于 ThreadLocal，请求线程的鉴权信息不会传播到 `workflowExecutor` 线程。
   - 修复：权限校验留在请求线程（create 阶段逐库校验），异步执行只用已校验的 kbIds。
