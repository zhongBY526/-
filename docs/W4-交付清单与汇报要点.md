## 三、失败案例归因（3 条，开发过程真实问题）与优化措施（1 条）

> 本次 15 题评测 0 失败；以下 3 条为开发/调试过程中定位并修复的真实缺陷，可作为归因分析素材。

1. **Skill R5 层次序数误报**（已修复）
   - 现象：DRAFT 草稿明明有"一、自查对象和范围"，R5 仍报"缺少上级一、级"，score 被误扣到 72。
   - 根因：正则 `(?m)^一、` 在原始文本上匹配，而公文正文行首是全角空格 U+3000 缩进，"一、"不在行首。
   - 修复：正则改为 `^[\s\u3000]*一、`，行解析先把全角空格归一化；重跑后 score=100。
   - 教训：中文公文场景必须考虑全角空白；规则引擎要用真实生成样本回归。

2. **JSON 模型无法生成公文正文**（已修复）
   - 现象：复用 `openAiJsonChatModel` 生成草稿，输出被强制成 JSON 而非公文文本。
   - 根因：该模型配置了 `response_format=json_object`，适合结构化抽取/分类，不适合自由文本。
   - 修复：新增 `WorkflowModelConfig.workflowChatModel`（普通文本，temperature 0.3）；JSON 模型只用于意图分类。

3. **异步线程丢失登录上下文**（已规避）
   - 现象：工作流丢进线程池后调用 `requireAccess` 抛未授权。
   - 根因：`UserContext` 基于 ThreadLocal，请求线程的鉴权信息不会传播到 `workflowExecutor` 线程。
   - 修复：权限校验留在请求线程（create 阶段逐库校验），异步执行只用已校验的 kbIds。

**优化措施（有数据支撑）**：无答案题平均耗时 9.7s（触发 2 次检索重试）vs 有答案题 4.1s（0 重试），且拒答时仍附带 3 条不相关引用。
措施：首轮检索 rerank top1 分数低于阈值时直接确定性拒答、跳过改写重试，并不再展示不相关引用——预期无答案题延迟从 ~10s 降到 ~4s，拒答更干净。
